# 使用说明

## 一、只是想把书翻成中文（最快路径）

1. 打开 **[新建翻译任务](../../issues/new?template=translate.yml)**
2. **把 PDF / Word 直接拖进「文件」框**——拖进去后会变成一行链接，那就是上传成功了
3. 选「输出形式」：
   - **原位版式保留**：译文覆盖原文，图片、公式、表格位置完全不动 ← 教材通读用这个
   - **双语对照**：原文与译文对照 ← 精读、校对用这个
   - **扫描版 OCR 翻译**：整页是图片的老书、扫描件用这个
4. 选「目标语言」，点 **Submit new issue**
5. 等 1-5 分钟。机器人会在这条 Issue 下面回复：

```
✅ 翻译完成
直接下载：https://github.com/.../raw/results/...
```

> ⏱ 时间参考：30 页约 1 分钟，120 页约 1 分钟；教材那种密排页会慢一些。
> 💾 下载链接保留 **7 天**，之后自动清理。
> 📦 单个文件 ≤ **25MB**（GitHub 附件上限），更大的书请拆分。

## 二、翻出来不对怎么办

| 现象 | 原因与对策 |
|---|---|
| 一点没翻，或提示"没有文本层" | 这是扫描件，请把「输出形式」改成**扫描版 OCR 翻译** |
| 公式/符号变成空白 | 极少数情况下是原 PDF 的字体把符号编码坏了（PDF 本身的毛病），可换「双语对照」模式对照原文看 |
| 术语不统一（同一词前后译法不同） | 在术语表里把这个词固定下来（见下面第三节），重跑即可 |
| 目录、页码没翻 | Word 里含域代码的段落会整段跳过，这是有意为之——翻了会破坏版面 |
| 失败 | 点机器人回复里的运行记录看日志；常见原因：文件加密、超过 25MB、密钥额度不足 |

## 三、让术语按你的偏好翻（仓库所有者或协作者）

编辑仓库里的 `glossary.json`，格式是分组 + `英文: 中文`：

```json
{
  "微观经济学": {
    "firm": "厂商",
    "marginal cost": "边际成本"
  }
}
```

内置 **300+ 条经管术语**（微观、宏观、金融会计、管理营销、统计计量），实测能把
`firm` 从模型默认的「企业」固定成「厂商」。

三个要点：

- **按词边界匹配**：写 `firm` 不会误命中 `confirm`；写 `finance` 不会命中 `financial`。
- **只注入本批出现的词**：术语表再大也不会把提示词塞满（每批最多 20 条）。
- **改完自动生效**：术语表会进翻译缓存的键，改了它旧译文会自动重算，不会静默用旧结果。

## 四、自己搭一份（Fork，用自己的密钥）

不想用别人的额度，就 fork 一份自己用：

1. 点右上角 **Fork** 建一个自己的副本
2. 准备 `profiles.json`（格式见 [README](../README.md#给仓库所有者配置密钥一次性)），
   里面填**你自己的** API 密钥
3. 你的仓库 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name 填 `PROFILES_JSON`，Secret 粘贴 `profiles.json` 的全文
4. **Settings → Actions → General**，确认允许运行工作流
5. 之后用法完全一样：开 Issue、拖文件、等链接

> 密钥只存在于仓库 Secret 里，**不会出现在代码、日志或 Issue 中**（工作流运行时才临时注入，
> 用完即焚）。使用者永远看不到它。

## 五、密钥花多少钱

按实测（DeepSeek-V4-Flash 关思考，硅基流动单价 $0.14 / $0.28 每百万 tokens）：

| 篇幅 | 成本 | 时间 |
|---|---|---|
| 30 页 | ≈ ¥0.015 | 约 1 分钟 |
| 120 页 | ≈ ¥0.06 | 约 1 分钟 |
| 700 页教材 | ≈ ¥1.4 | 十几分钟 |

同一个文件重跑几乎不花钱（译文有缓存，且术语表没变的话直接命中）。
